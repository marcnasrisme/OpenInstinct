## Part 1 — Code review

### Summary

The code is well organized and strictly typed, but the safety model relies on
prompts. Approvals for email, calendar and saved-card fills were removed on
purpose in upstream commit `4cf6404` ("Remove Eve tool approvals while
retaining Link purchase approval", 2026-10-02). With Link purchases now
disabled, no consequential action needs a person's approval. These are the
same failures that hurt Instinct.

### What looks good

- Strict TypeScript, custom oxlint boundary rules, knip, and many unit tests.
- Gmail output is regex-redacted (OTP codes, API keys, card numbers; `agent/lib/google-workspace/gmail.ts:246–264`), and tool descriptions tell the model to treat that content as untrusted.
- The scheduled worker gets read-only Gmail and Calendar tools (`gmail.ts:74`, `calendar.ts:58`). That pattern is worth copying.
- The Linq webhook verifier fails closed (`linq.ts:51–58`), and unverified senders never get a principal (`linq.ts:352–360`).
- The vault encrypts each item with AES-GCM, and autofill keeps values on the server and out of tool inputs.

### Verdict

**Request changes.** Do not connect real Gmail, a real calendar or saved cards
until PRs 1–2 of the fix plan are merged.

### Phased remediation

- **Phase A (before real accounts):** items 1, 3 and the approval work itself (plan PRs 1–2).
- **Phase B (before inviting anyone else):** owner allowlist, audit log, evals in CI (plan PRs 3–4, plus the CI eval job in the testing strategy).
- **Phase C (before new channels):** Linq extraction and model choice (plan PRs 5–6).
- **Backlog:** delete data when Google is disconnected (finding 9), and an eve upgrade when 1.0 ships.
